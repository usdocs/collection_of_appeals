# Сбор обращений абонентов (FastAPI + Pydantic)

Сервис на FastAPI для приёма и сохранения обращений абонентов.
Все входные данные валидируются моделями Pydantic (v2).

## Возможности

- Эндпоинт `POST /appeal` принимает фамилию, имя, дату рождения,
  номер телефона и e-mail; результат сохраняется на диск в JSON-файл
  (папка `data/`, один файл на обращение);
- поддерживаются **причина обращения** (перечисление: «нет доступа
  к сети», «не работает телефон», «не приходят письма») и
  **дата/время обнаружения проблемы**;
- в одном запросе может быть **несколько причин** обращения —
  поле `reasons` принимает список.

## Установка и запуск (через uv)

```bash
uv sync                      # создать .venv и установить зависимости
uv run uvicorn main:app --reload
```

- API: http://127.0.0.1:8000
- Интерактивная документация (Swagger): http://127.0.0.1:8000/docs

## Эндпоинты

| Метод | Путь | Описание |
| ----- | ---- | -------- |
| `POST` | `/appeal` | Принять обращение: валидация через Pydantic и сохранение в JSON |

### Имена полей

Поля передаются под именами полей Pydantic-модели:
`last_name`, `first_name`, `birth_date`, `phone`, `email`,
`reasons`, `detected_at`.

### Пример запроса (одна причина)

```bash
curl -s -X POST http://127.0.0.1:8000/appeal \
  -H "Content-Type: application/json" \
  -d '{
    "last_name": "Иванов",
    "first_name": "Иван",
    "birth_date": "1990-05-15",
    "phone": "+79001234567",
    "email": "ivanov@example.com",
    "reasons": ["нет доступа к сети"],
    "detected_at": "2026-11-08T14:30:00"
  }'
```

### Пример запроса (несколько причин)

```bash
curl -s -X POST http://127.0.0.1:8000/appeal \
  -H "Content-Type: application/json" \
  -d '{
    "last_name": "Петрова",
    "first_name": "Мария",
    "birth_date": "1985-01-01",
    "phone": "89161234567",
    "email": "petrova@test.ru",
    "reasons": ["не работает телефон", "не приходят письма"],
    "detected_at": "2026-11-09T08:00:00"
  }'
```

Ответ — `201 Created`, в теле — принятое обращение (валидированное Pydantic-моделью).
В папке `data/` появляется JSON-файл, содержащий переданные атрибуты.

## Валидация

- **Фамилия и имя** — с заглавной буквы, только буквы кириллицы
  (цифры, пробелы и спецсимволы отклоняются): `^А-ЯЁ[а-яё]+$`;
- **Номер телефона** — 11 цифр, начинается с `+7` или `8`;
- **E-mail** — `адрес@домен.зона`, например `ivanov@example.com`;
- **Дата рождения** — формат `ГГГГ-ММ-ДД` (ISO 8601), не может быть в будущем;
- **Причина обращения** — только значения перечисления `AppealReason`,
  без повторений;
- **Дата и время обнаружения проблемы** — ISO 8601, не может быть в будущем.

Невалидные данные отклоняются с кодом `422 Unprocessable Entity`
и понятным описанием ошибки.

Ошибки записи на диск (нет места, нет прав) возвращают
`500 Internal Server Error` с сообщением «Не удалось сохранить
обращение на диск».
